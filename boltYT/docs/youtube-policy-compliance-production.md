# YouTube Policy-Safe Production Rules

이 문서는 정책을 "우회"하기 위한 문서가 아니라, 자동 제작물이 YouTube에서 오해를 만들지 않도록 사전에 줄이는 제작 기준이다.

## 제작 원칙

1. AI 재구성은 실제 자료처럼 말하지 않는다.
   - 금지 표현: "실제 CCTV", "실제 영상", "단독 영상", "원본 영상".
   - 허용 표현: "당시 상황을 바탕으로 재구성", "이해를 돕기 위한 재현 이미지".

2. 현실적으로 보이는 AI/합성 장면은 업로드 설명에서 고지한다.
   - 권장 문구: `일부 장면은 이해를 돕기 위한 AI 재구성입니다. 실제 사진/영상은 출처가 확인된 자료만 사용했습니다.`
   - 업로드 시 YouTube Studio의 altered content 항목도 확인한다.

3. 사건/사고/범죄 주제는 충격 유도보다 맥락을 우선한다.
   - 유혈, 시신, 사고 순간, 폭력 장면은 썸네일/첫 화면/반복 컷의 중심으로 쓰지 않는다.
   - 필요한 경우 문서, 지도, 장소, 시간표, 흐릿한 아카이브 컷으로 대체한다.

4. 제목/썸네일/설명은 영상 안의 실제 내용과 일치해야 한다.
   - 제목에서 "CCTV 공개"라고 하면 실제 공개 영상 또는 출처가 확인된 영상이 있어야 한다.
   - 없으면 "타임라인 분석", "보도자료 기반 정리", "사건 재구성"처럼 기대치를 낮춘다.

5. 재사용/대량생산형으로 보이지 않게 만든다.
   - 기사 읽기, 이미지 슬라이드쇼, 반복 템플릿만으로 구성하지 않는다.
   - 각 영상마다 사건 순서, 원본 해설, 자료 해석, 반론/오해 정리, 현재 결론을 넣는다.

6. 검색/추천 메타데이터는 영상 내용과 정확히 맞춘다.
   - YouTube 검색은 관련성, 참여도, 품질 신호를 함께 본다. 제목, 설명, 태그, 실제 영상 내용이 검색어와 맞아야 한다.
   - 추천은 개별 시청자의 시청 기록, 검색 기록, 구독, 좋아요/싫어요, 만족도 신호에 영향을 받으므로 키워드만으로 보장할 수 없다.
   - 태그는 오타/동의어 보조용으로만 제한한다. 제목, 썸네일, 설명이 더 중요하다.
   - 해시태그는 직접 관련 있는 1~3개만 쓴다. 과도하거나 무관한 해시태그는 스팸/오해 리스크가 된다.
   - 설명 첫 줄에는 주제와 시청자가 얻게 될 내용을 분명히 쓰고, 롱폼은 챕터를 포함한다.

## 숏폼과 롱폼 차이

### 숏폼

- 강한 훅과 빠른 컷은 유지하되, 실제 자료와 재구성 자료를 혼동시키지 않는다.
- 30~60초 안에서도 출처 기반 사실 2~4개만 다룬다.
- 자극적인 미해결/범인 단정 표현을 피하고, "확인된 것은 여기까지"로 끝낸다.

### 롱폼

- 쇼츠식 6~8초 인터럽트를 반복하지 않는다.
- 10~18개 씬, 챕터형 구조, 6~12분 목표를 기본으로 한다.
- 실제 영상 비율은 자료가 충분할 때만 높인다. 비용 절감/자료 부족 모드에서는 문서/지도/기사/아카이브 이미지/재구성 컷을 모션 설계해서 근거 밀도를 만든다.
- 마지막은 갑자기 멈추지 않고 현재 상황, 남은 의문, 확인 가능한 출처, 부드러운 CTA로 마무리한다.

## 자동 게이트

코드에서는 `src/lib/youtube-policy-risk.ts`가 다음 위험을 감지한다.

- AI 재구성을 실제 영상처럼 주장하는 경우
- 합성/재구성 고지가 필요한데 설명에 고지가 없는 경우
- 출처 없는 단정 표현이 있는 경우
- 그래픽/충격 유도 표현이 있는 경우
- 출처 앵커가 약한 장면이 과도하게 많은 경우
- 반복 템플릿/대량생산형 패턴이 감지되는 경우

이 게이트는 법률 검토가 아니라 제작 전 품질/정책 리스크를 낮추는 안전장치다.

## 프리프로덕션 제작성 게이트

제작 타입은 분리한다.

- `documentary/research`: 실제 자료, 기사, 영상, 타임라인, 출처 앵커 중심
- `animation`: 캐릭터 바이블, 세계관, 갈등, 키포즈, 컷 편집 중심
  - 하위 `production_family`: `character_micro_sitcom`, `storytime_animation`, `slapstick_no_dialogue`, `animated_explainer`, `history_comedy`, `infographic_motion`, `whiteboard_lesson`, `myth_horror_story`, `meme_original`, `kids_fable`
- `standard`: 일반 AI 자동 생성

코드에서는 `src/lib/topic-production-readiness.ts`가 자료 기반 스크립트 생성 전에 주제와 수집 자료의 제작성을 먼저 평가한다.

- 본문/설명/출처 텍스트가 있는 팩트 자료가 있는지
- 롱폼을 버틸 만큼 자료 개수와 본문 밀도가 충분한지
- 사건 날짜, 타임라인, 팩트, 출처 다양성이 있는지
- 실제 영상/이미지 자료가 있는지
- 자료가 약할 때 어떤 각도로 좁혀야 하는지

치명적인 경우에는 스크립트 생성을 보류한다. 롱폼만 약한 경우에는 "타임라인 검증형", "문서/보도자료 해석형",
"핵심 팩트 체크형" 같은 좁은 제작 각도로 재기획하고, 그 지시를 스크립트 프롬프트에 주입한다.

이 단계의 목적은 저품질 결과를 렌더 후에 고치는 것이 아니라, 애초에 약한 입력으로 긴 영상을 만들지 않게 막는 것이다.

애니메이션 제작은 `src/lib/animation-production.ts`가 별도로 평가한다.

- 주인공 단서가 있는지
- 갈등/반전/목표가 있는지
- 롱폼을 버틸 3막 구조가 필요한지
- 캐릭터 외형/의상/색상/세계관을 모든 visual prompt에 반복해야 하는지
- 어떤 애니메이션 제작 패밀리에 해당하는지
- 해당 패밀리의 품질 게이트와 리스크 제어가 무엇인지

애니메이션 샷은 `selection_provider: "animation"`으로 표시하고, 미디어 단계에서 실사 사진/영상 검색을 건너뛰고 AI 키포즈 이미지를 생성한다.
이 경로는 실제 사건 자료처럼 보이려는 목적이 아니므로 documentary의 출처 카드/뉴스 검색 기준과 분리한다.
레퍼런스 채널은 복제 대상이 아니라 공개적으로 관찰 가능한 포맷 패턴으로만 사용한다. 특정 채널의 캐릭터, 고유 그래픽, 대사, 음원, 반복 농담을 그대로 따라 하는 방식은 정책/저작권/품질 리스크로 본다.

## 자동 메타데이터 생성

코드에서는 `src/lib/youtube-metadata.ts`가 다음을 생성한다.

- 제목: 주제와 영상 형식에 맞춘 검색 친화 문구
- 설명 첫 줄: 주제, 사건 흐름, 자료 기반 정리 여부
- 핵심 키워드: 제목/설명과 같은 용어를 반복 없이 정리
- 챕터: 롱폼에서 시청 유지와 탐색을 돕는 타임스탬프
- 출처: 장면에 연결된 뉴스/자료 출처 요약
- 고지: AI 재구성 장면이 있을 때 설명에 명시
- 태그/해시태그: 직접 관련 있는 보조 키워드만 제한적으로 생성
- 썸네일 패키징: 짧은 썸네일 제목, 서브타이틀, 주제별 프리셋, 액센트 색상

## 초반 유지율/썸네일 게이트

코드에서는 `src/lib/youtube-retention.ts`가 승인 전 다음을 검사한다.

- 첫 문장이 인사말/소개형으로 시작하는지
- 첫 문장이 질문, 반전, 핵심 주장 같은 훅을 포함하는지
- 쇼츠 첫 10초에 충분한 컷 수와 영상/모션 비중이 있는지
- 롱폼 첫 씬이 과도하게 길지 않은지
- 제목 핵심어와 초반 나레이션이 맞는지

승인 단계에서는 이 게이트를 통과하지 못한 영상의 업로드 큐 등록을 막는다.
스크립트 생성 단계에서는 약한 첫 문장을 자동으로 질문형 훅으로 보정한다.

썸네일은 승인 시 `src/lib/thumbnail.ts`로 자동 생성해 `uploads.thumbnail_path`에 저장하고,
YouTube 업로드 서버가 업로드 후 `youtube.thumbnails.set`으로 커스텀 썸네일을 적용한다.

## 프로덕션 품질 게이트

코드에서는 `src/lib/youtube-production-quality.ts`가 승인 전 최종 품질 병목을 한 번에 검사한다.

- 연속 TTS 또는 씬별 TTS 존재 여부
- BGM 존재 여부와 Preview 단계 자동 복원/자동 선택 여부
- 썸네일 계획과 실제 생성 가능 여부
- 실제 영상 컷 비율, 설계된 자료화면 비율, 모션 비주얼 비율, 텍스트 씬 과다 여부
- 출처 앵커 샷 비율, 저신뢰 샷 비율, AI 재구성 비율
- 증거/문서/아카이브 자리에 일반 스톡 자료가 과도하게 섞였는지 여부
- 단어 타이밍 기반 자막 싱크 비율과 TTS 밀도
- 갑자기 끊기는 엔딩, 너무 짧은 마지막 씬, 결론 없는 마무리
- 롱폼 최소 구조와 최소 길이 리스크

Preview의 승인 버튼은 이 게이트를 통과해야만 렌더를 시작한다. BGM이 없으면 먼저 자동 선택을 시도하고,
썸네일은 렌더 전에 생성한다. 품질 점수와 세부 이슈는 `renders.qc_result_json`에 저장된다.

## 자동 품질 복구

코드에서는 `src/lib/youtube-production-repair.ts`와 Preview 승인 루프가 저품질 결과를 바로 렌더하지 않고 먼저 복구한다.

- 엔딩이 갑자기 끊기면 마지막 문장을 현재 결론/남은 의문으로 보강하고 연속 TTS를 다시 생성한다.
- TTS가 없으면 연속 나레이션을 다시 생성한다.
- 정적인 이미지 씬에는 샷 모션, 전환, 로워서드 출처 표시, 지도/문서/콜아웃 처리를 추가한다.
- 미디어 검색 단계에서는 관련성 점수가 낮은 고해상도 스톡 자료를 거르고, 생성 후에도 약한 샷만 재검색/교체한다.
- 핵심 자료 자리에 Pexels/Pixabay 같은 일반 스톡이 과도하게 들어오면 Preview 승인 단계에서 차단한다.
- 실제 사진/영상 다운로드가 막히거나 관련 자료가 없으면 랜덤 스톡 대신 출처 기반 SVG 자료 카드를 만든다. 이 카드는 원본 사진/영상이라고 주장하지 않는다.
- 실제 영상 비율 부족은 기본 차단 사유가 아니다. 대신 대부분의 시각 씬이 모션 자료화면으로 설계됐는지 검사한다.
- AI 영상 생성은 선택적 hero shot에만 쓰는 비용 옵션이다. 기본 승인 루프는 FAL/API 키가 없어도 동작해야 한다.
- 자동 복구 후에도 품질 게이트를 통과하지 못하면 렌더와 업로드 큐 등록을 중단한다.

원칙은 단순하다. 저품질 영상은 업로드 큐에 들어가지 않는다. 자동 보강으로 품질을 만들 수 없으면 실패로 드러낸다.
